# 顧客データ取扱い説明

## PoCで扱うデータ

PoCでは、合意した範囲のFAQ、規約、料金表、社内ルール、または匿名化・サンプル化した文書を使います。高リスク質問ケースは、返金、解約、料金、契約条件、期限、資格条件など、誤回答時の影響が大きい領域に絞って作成します。

顧客データをそのままGitHub Actionsに載せる前提にはしません。営業デモと公開CIでは、sample、mock、dummy、aggregate metadata のみを扱います。

## GitHub Actions / artifacts / logs に載せないデータ

- APIキー、アクセストークン、認証情報
- 顧客の非公開文書全文
- 顧客固有の問い合わせ本文、回答本文、検索根拠本文
- raw JSONL、full report、FAISS index、FAISS meta raw payload
- 接続検証時のraw HTTP payload

## サンプル/モック/匿名化データの扱い

営業デモやCIでは、公開して問題ないサンプルFAQとモック回答だけを使います。顧客名、契約名、実際の問い合わせ、内部URL、個人情報は入れません。

顧客文書を使うPoCでは、保存場所、外部送信有無、ログ保持期間、アクセス可能者、削除方法を事前に合意します。

## APIキー・顧客文書・回答本文の扱い

APIキーは環境変数または顧客側の秘密情報管理に置き、レポート、ログ、artifactには出しません。

顧客文書や回答本文を評価に使う場合も、顧客提出レポートには必要最小限の要約だけを載せます。全文の質問、期待回答、AI回答、retrieved evidence本文は、合意した運用詳細の範囲でのみ扱います。

## 顧客提出レポートに含めるもの

- 本番反映可否
- `policy_status` とその意味
- 重大失敗件数、S1 pass rate、overall pass rate
- 重大リスクの領域別要約
- 改善事項と次の推奨
- 月次Monitorで継続確認すべき領域

## 顧客提出レポートに含めないもの

- APIキー、トークン、秘密情報
- ローカル絶対パス、CI workspace path、一時作業ディレクトリ名、内部ディレクトリ構造
- 顧客文書全文、問い合わせ全文、AI回答全文
- raw JSONL、full debug report、検索index、接続検証raw payload

## 本格運用時の考え方

本格運用では、顧客環境、private runner、顧客管理のobject storage、閉域または制限付きネットワーク、既存監査ログ基盤との接続を前提に設計します。

Proof Gate は、RAG本体の代替ではありません。RAG AIを安全に変更・運用するための品質ゲートとして、必要な証跡だけを残し、顧客データ露出を最小化します。

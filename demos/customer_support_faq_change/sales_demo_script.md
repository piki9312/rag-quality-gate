# Customer Support FAQ変更事故 2分営業デモ台本

## 0:00-0:20 導入

今日は、Proof Gate付き RAG AI導入診断PoCで何を確認できるかを2分で見せます。

このデモでは、FAQが更新された後もAIが古い条件で答えてしまう変更事故を扱います。返金、解約、料金、契約条件のような領域では、文章が自然でも条件が古いだけで顧客影響が出ます。

## 0:20-0:50 Before

`reports/before_stale_v1/gate-report.md` を開きます。

見る場所は3つです。

- `1. 本番反映判定`: `NG`、`policy_status: BLOCK`
- `4. 実行結果サマリ`: S1 pass rate 0.0%、overall pass rate 16.7%
- `5. S1重大失敗一覧`: 返金・解約・契約などの高リスク質問

トーク例:

AIの回答は一見自然ですが、FAQ v1 の古い条件で答えています。現在のFAQ v2とは違うため、そのまま本番に出すと顧客向けの誤案内になります。Proof Gate はこれを S1重大失敗として止め、`policy_status=BLOCK` にします。

## 0:50-1:15 Proof Gateが見ていること

Proof Gate が見ているのは、文章のうまさだけではありません。現在のFAQ・規約・料金表に照らして、高リスク質問に安全に答えられているかを確認しています。

例:

- 返金できる条件を古く案内していないか
- 無料トライアル終了後の課金を誤案内していないか
- 契約条件や自動更新条件を間違えていないか

## 1:15-1:40 After

`reports/after_v2_reference/gate-report.md` を開きます。

見る場所は before と同じです。

- `1. 本番反映判定`: `OK`、`policy_status: PASS`
- `4. 実行結果サマリ`: S1 pass rate 100.0%、overall pass rate 100.0%
- `5. S1重大失敗一覧`: 該当なし

トーク例:

修正後は、同じ高リスク質問でS1重大失敗が0件になっています。beforeの `BLOCK` から、afterでは `PASS`、本番反映可の判断に変わりました。これは、FAQ変更後の改善を同じ条件で説明できることを意味します。

## 1:40-1:55 月額Monitorにつながる理由

FAQ、規約、料金表、プロンプトは導入後も変わります。一度安全だったAIでも、変更後に古い回答や危険な回答へ戻ることがあります。

Proof Gate Monitor では、高リスク質問を定期的に再実行し、S1重大失敗、未解決アクション、レビュー対象の変化を継続確認します。

## 1:55-2:00 クロージング

Proof Gate は、RAGを作るだけではなく、安全に導入し、変更後も継続監視するための品質ゲートです。PoCでは、御社のFAQ・規約・料金表で同じ診断を行い、改善余地とMonitor移行の判断材料を提出します。

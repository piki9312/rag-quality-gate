# 08_顧客候補DB設計

## Notion Databaseの目的

- 初期ターゲット企業を一覧化する
- 仮説の強さ、接触状況、学びを蓄積する
- 営業・ヒアリング・PoC提案の進捗を可視化する

## 推奨プロパティ設計

| プロパティ名 | 型 | 用途 | 記入例 |
|---|---|---|---|
| 企業名 | Title | 会社名の主キー | 株式会社○○ |
| 種別 | Select | ベンダー / AI導入支援 / DX支援 / エンド企業 | RAG導入会社 |
| 所在地 | Text | 商圏・訪問可否の把握 | 東京 |
| 提供サービス | Multi-select | 何を提供している会社か | RAG導入, FAQボット, DX支援 |
| 想定課題 | Text | 仮説ベースの痛み | PoC後の品質説明が弱い |
| 既存AI/RAG導入有無 | Select | 現在の導入状態 | 既存導入あり |
| 接触先 | Text | 役職・担当者名 | 営業責任者 / CTO |
| 仮説スコア | Number | 刺さりそう度の定量化 | 8 |
| 初回接触日 | Date | 接触開始日 | 2026-05-20 |
| ステータス | Select | 未接触 / 連絡済 / 日程調整中 / ヒアリング済 / 提案済 / 見送り | ヒアリング済 |
| 反応 | Select | 強い / 普通 / 弱い / なし | 強い |
| 次アクション | Text | 次にやること | 提案資料送付 |
| 学び | Text | ヒアリングで得た知見 | 保守メニュー化ニーズ高い |
| 優先度 | Select | P0 / P1 / P2 | P0 |

## 補助プロパティ候補

- 案件数規模
- 顧客業界
- ベンダー案件の比率
- 保守契約の有無
- 紹介元
- 最終更新日

## 仮説スコアの付け方

| 条件 | 点数 |
|---|---|
| RAG/AIチャットボット導入会社である | +3 |
| 顧客向けPoCや納品支援をしている | +2 |
| FAQ/規約/社内文書などの高リスク文書を扱う | +2 |
| 保守運用や月額支援を提供している | +2 |
| 品質説明・運用負荷に関する発信がある | +1 |

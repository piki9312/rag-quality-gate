# 07_ヒアリング設計

## 目的

- 誰のどの痛みに、どの商品が刺さるかを見極める
- 予算化可能性と継続運用化の可能性を確認する
- ベンダー向け仮説とエンド企業向け仮説を切り分ける

## ベンダー向けヒアリング

### 必須質問

| 質問 | ねらい | 深掘り例 |
|---|---|---|
| PoC後に本番移行しない理由は何が多いですか？ | 本番化の阻害要因を把握する | 品質、稟議、運用、予算のどれが大きいか |
| 顧客に品質をどう説明していますか？ | 現状の説明手段を確認する | レポート、口頭、スプレッドシート、デモのどれか |
| 納品後の誤回答責任をどう捉えていますか？ | 痛みの強さを確認する | 契約上の責任、炎上懸念、サポート負荷 |
| 品質レポートを提案に使えると思いますか？ | 営業導線への適合性を確認する | 提案段階、PoC報告、納品時のどこで使うか |
| 1案件あたり10万〜30万円の品質レポート費用を案件原価に入れられますか？ | 単発売上の成立性を確認する | 原価化できるか、顧客請求できるか |
| 月額5万〜20万円の変更時チェックを顧客への保守メニューにできますか？ | 継続収益化の可能性を確認する | 誰が売るか、どの契約に乗せるか |

### 補助質問

- 現在のPoCから本番移行率はどの程度か
- どの業界・案件で品質説明が特に難しいか
- 返金・解約・料金・規約のような高リスク論点は誰が確認しているか
- 品質事故が起きた時、営業とDeliveryのどちらがより痛むか
- 顧客提出用の標準資料が今あるか

### 見るべきシグナル

- 品質説明の痛みが具体的か
- 原価計上または保守メニュー化の意思があるか
- 複数案件へ横展開できそうか
- レポート価値への反応が強いか

## エンド企業向けヒアリング

### 必須質問

| 質問 | ねらい | 深掘り例 |
|---|---|---|
| AI回答の最終責任者は誰ですか？ | 決裁者と責任構造を把握する | CS、事業責任者、情報システム、法務 |
| 本番導入判断の基準は何ですか？ | 本番Goの判断材料を知る | 精度、運用負荷、説明責任、炎上リスク |
| 返金・解約・料金・規約回答の確認方法はどうしていますか？ | 現状の確認フローを確認する | 人手、ベンダー任せ、サンプリング |
| FAQ/規約更新後の再確認方法はありますか？ | 継続ニーズの有無を知る | 毎回確認、ほぼ未確認、事故後対応 |
| 社内説明用レポートは必要ですか？ | レポート価値の有無を確認する | 役員報告、稟議、監査、法務レビュー |

### 補助質問

- 重大誤回答として特に避けたい領域は何か
- ベンダー評価や受入判断に使える資料が欲しいか
- 月次または変更時チェックに予算を持てるか
- 過去にFAQ更新後の事故があったか

### 見るべきシグナル

- 本番導入判断が属人的で困っているか
- 返金・解約・料金・規約などの高リスク論点を明示できるか
- 社内説明レポートに対する需要があるか
- 変更時チェックを定例運用にしたいか

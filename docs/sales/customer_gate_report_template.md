# 顧客提出版 Gate Report テンプレート

> このテンプレートは、Proof Gate の評価結果を顧客責任者向けに共有するためのひな形です。詳細なケース一覧、CLI実行条件、生ログ、内部メトリクスは別紙に分けてください。

## 1. 基本情報

- **顧客名**: `株式会社〇〇`
- **対象AI名**: `顧客対応FAQ AI / 社内問い合わせAI / 既存RAG診断対象`
- **対象文書**: `FAQ、利用規約、料金表、社内ルール など`
- **変更イベント**: `FAQ更新 / 料金改定 / 規約改定 / プロンプト更新 / モデル変更`
- **評価実施日**: `YYYY-MM-DD`
- **評価対象期間**: `初回PoC / 改善後再評価 / 月次Monitor`
- **execution_mode**: `real / external_real / mock / ci_mock`

## 2. 結論

- **総合判定**: `PASS / BLOCKED / NEEDS_FIX / REVIEW_REQUIRED`
- **日本語要約**: `例: 重大誤回答リスクが残るため、本番公開前に修正が必要です。`

### 判定の読み方

- **PASS**: 指定したケース・対象文書・指定モデル・指定設定では、今回の検査基準を満たしています。
- **BLOCKED**: 重大誤回答リスクが検出されており、そのままの公開は推奨できません。
- **NEEDS_FIX**: 即時停止レベルではないものの、改善してから再評価すべき項目があります。
- **REVIEW_REQUIRED**: 業務責任者・運用責任者による確認が必要です。

### Simulation note

- `mock / ci_mock` は simulation であり、実システム品質の証跡ではありません。
- 顧客向け判断資料では `execution_mode` を必ず明記してください。

## 3. 重大失敗

| 重大誤回答リスク | 該当質問 | 想定される顧客影響 | 対応優先度 |
|---|---|---|---|
| `例: 返金条件の誤案内` | `例: キャンペーン商品は7日以内なら返金できますか。` | `返金トラブル、案内不整合、CS負荷増加` | `最優先` |
| `例: 解約期限の誤案内` | `例: 無料トライアル中に解約すれば課金されませんか。` | `請求トラブル、信頼低下` | `最優先` |

## 4. 改善事項

- **文書修正**: `例: FAQ / 規約 / 料金表の条件を最新化する`
- **プロンプト修正**: `例: 高リスク回答では根拠文書にない断定を避ける`
- **回答ルール修正**: `例: 返金・解約・契約条件は公開条件のみ案内する`
- **評価ケース追加**: `例: 新しい問い合わせ傾向を high-risk cases に追加する`

## 5. 次の推奨

### すぐ直すべきこと

- `例: 重大失敗が出た質問に対応する文書・回答ルールを修正する`
- `例: 修正後に同じ高リスク質問セットで再評価する`

### 次回評価で見るべきこと

- `例: 料金改定後の誤案内がないか`
- `例: 契約条件や返金条件に関する新しい問い合わせ傾向`

### 継続監視が必要な領域

- `例: FAQ・料金表・規約の更新が多い領域`
- `例: 返金・解約・契約条件など顧客影響が大きい領域`

## 6. 責任分界と公開判断

- Proof Gate は、重大誤回答リスクの**検査**と**可視化**を支援します。
- Proof Gate は、AI の安全を完全保証するものではありません。
- `PASS` は「対象範囲での診断結果」であり、全質問や法的適合性を保証するものではありません。
- 最終的な公開判断は、顧客側の業務責任者・運用責任者と合意して行ってください。
- 外部RAGや外部APIの可用性・認証・運用設定は、顧客またはシステム提供側の責任範囲です。

# 簡易RAG構築と本格RAG構築の違い

## 簡易RAG構築

- **目的**: PoC検証・重大誤回答リスクの確認
- **対象**: 限定された FAQ / 規約 / 料金表 / ヘルプ文書
- **特徴**:
  - 小さく早く作る
  - 本番UI / 認証 / 権限管理は最小限または対象外
  - 評価ケースと Gate 判定を重視する
  - 商談・検証・社内判断向け

## 本格RAG構築

- **目的**: 実運用・顧客対応・社内展開
- **対象**: 本番文書群・運用ルール・権限管理
- **特徴**:
  - 認証
  - 権限
  - UI
  - ログ
  - 監視
  - SLA
  - 運用フロー
  - セキュリティ要件
  - 継続評価

## 誤解防止

PoCの簡易RAGは、本番RAGの完成版ではありません。目的は、対象文書に対してAI回答の重大リスクを検出し、導入判断に必要な論点を明らかにすることです。

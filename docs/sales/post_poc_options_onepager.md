# PoC後の選択肢：Build / Improve / Monitor

Proof Gate PoC の後は、課題の種類と導入段階に応じて、次の3つの選択肢があります。

## 1. Build：本格RAG構築

- **対象**: まだ顧客対応AI / FAQ RAG がない企業
- **提供内容**:
  - FAQ / 規約 / 料金表の整理
  - RAG構築
  - 回答ルール設計
  - Proof Gate評価ケース作成
  - 初回Gate判定
- **成果物**:
  - 動作するRAG
  - 評価ケース
  - Gate report
  - 運用手順

## 2. Improve：既存RAG改善支援

- **対象**: すでにRAG / チャットボットがある企業
- **提供内容**:
  - 現状診断
  - 重大誤回答ケース抽出
  - 文書・プロンプト・検索設定の改善提案
  - Before / After評価
- **成果物**:
  - 診断レポート
  - 改善案
  - Before / After report
  - 改善後Gate判定

## 3. Monitor：Proof Gate Monitor

- **対象**: PoC後も品質を維持したい企業
- **提供内容**:
  - 月次 / 変更時の評価実行
  - 重大誤回答検知
  - 変更差分の影響確認
  - 月次レポート
- **成果物**:
  - Monthly Gate Report
  - 失敗ケース一覧
  - 改善推奨
  - 品質推移

## 4. 選び方

- **AIがまだない** → Build
- **既存AIの品質に不安がある** → Improve
- **運用中AIの変更リスクを監視したい** → Monitor

## 5. 簡易RAG構築と本格RAG構築の違い

- **簡易RAG構築**: PoC検証と重大誤回答リスク確認が目的。対象文書を限定し、小さく早く作る。
- **本格RAG構築**: 実運用が目的。認証、権限、UI、ログ、監視、SLA、運用フロー、継続評価を含める。
- PoCの簡易RAGは、本番RAGの完成版ではありません。導入判断に必要な論点を明らかにするための検証スコープです。
